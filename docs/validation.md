## 亮度调节面板关闭回归

亮度写入完成与鼠标拖动结束现在分别处理：写入队列空闲时，仍在拖动的滑块继续保留面板保护；松手后不重建持有键盘焦点的滑块。刷新针对滑块实际所在的面板，焦点离开后再更新显示。

新增 8 项界面检查：写入中保持滑块、写入完成但仍在拖动、松手保留焦点、透明调暗层创建/关闭不抢焦点、连续二次调整、失败回退且面板保持打开、外部窗口关闭面板及 Escape 关闭。修复前的回归用例在“写入完成但仍在拖动”处失败，修复后全部通过。写入使用注入回调，调暗层透明度为 0，不改变真实屏幕亮度。

## 快捷面板布局选屏

面板顶部按桌面坐标绘制可点击屏幕轮廓，不常驻显示编号、型号或方位文字；名称只用于辅助功能和悬浮提示。亮度、缩放仅绑定选中的设备，其他控制通过“更多设置”展开。选择按设备 ID 保存，切换时保留展开状态；滚动高级控制时，选屏区域保持可见。旧逐屏折叠偏好不再隐藏控制。

## 多选亮度与输入源修复

“联调亮度”是面板会话内的独立模式：只展示亮度；点选、全选和取消选择不发送命令。每条亮度队列冻结明确的设备 ID 集合，执行时重新匹配当前设备，不扩展到全局同步或显示器组，也不应用组偏移；设备亮度上下限仍保留。写入或拖动期间不能更换目标或退出模式。混合亮度没有伪造的统一滑块值，失败后显示各屏实际值和错误；拔下的屏幕从选择中移除，重连不会自动加入。完成后恢复原单屏和更多设置状态。

只读输入源检测发现 ANT272ZQE 与 F27G30Q Pro 宣告 `11/12/0F`，实际当前值为 `07`；H25T7 使用标准 `11`。针对“仅宣告标准 HDMI/DP 且读到其非标准内部当前值”这一组合启用 `11→05、12→06、0F→07、10→08` 兼容映射，未知读值和普通显示器不套用。该模式与 [ddcutil 的直接硬件报告](https://github.com/rockowitz/ddcutil/issues/157) 一致，但本机的跨接口写入仍未实测。只读诊断可运行 `dotnet run --project tests/LumaDesk.WorkflowTests -- --read-inputs`。

输入源切换每次只写一次；随后最多五次只读检查，连续两次目标读值才确认成功。可读取但未保持目标输入时报错，断联或读回不足时明确显示未确认，不重试写入。界面更新当前输入状态，修复切回原输入被旧闭包状态跳过的问题，并提供重新读取入口。
